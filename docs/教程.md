# QQ 机器人 · 上手教程

这份教程假设你从零开始。全程大约 10 分钟。

---

## 0. 它到底是怎么工作的

```
你的 QQ（大号）
      │  私聊
      ▼
   QQ 服务器
      │
      ▼
 NapCat（登录一个小号，负责收发 QQ 消息）
      │  反向 WebSocket（NapCat 主动连到本插件）
      ▼
 本插件（监听 127.0.0.1:6700）
      │
      ▼
 DSH 里的一个 agent 会话（用你的电脑干活）
```

关键点：**本插件不登录 QQ**。登录 QQ 的是 NapCat，它把消息转给插件，插件再把回答交回 NapCat 发出去。

所以「NapCat 未连接」= 插件在等 NapCat 连过来，而 NapCat 那边还没配好地址。这不是报错。

---

## 1. 装 NapCat，登录小号

1. 打开 <https://napneko.github.io/guide/start-install>，按你的系统选一种安装方式（Windows 一般是 NapCatQQ 安装包或一键脚本）。
2. 启动后扫码登录**专门的小号**（不要用大号，第三方协议有封号风险）。
3. 登录成功后，NapCat 的 WebUI 一般在本机 `http://127.0.0.1:6099`，里面能看到账号在线。

> 已经装过 NapCat / AstrBot 的，跳到第 2 步。

---

## 2. 在 NapCat 里加一个「WebSocket 客户端」

NapCat 的「网络配置」里有三种：HTTP 服务器、WebSocket 服务器、**WebSocket 客户端**。
我们要的是最后一种（反向 WS：由 NapCat 主动连插件）。

新增一条，填：

| 字段 | 值 |
| --- | --- |
| 名称 | `dsh-qqbot`（随便） |
| URL | `ws://127.0.0.1:6700/` |
| 消息格式 | `array`（推荐）或 `string` 都行 |
| Token | 留空；若你填了，DSH 设置页的 Access Token 必须填同一个 |
| 心跳 | 默认即可 |

保存并启用。启用后回到 DSH 设置页，顶部状态应该变成绿色「NapCat 已连接」。

如果还是「未连接」，依次检查：

- 插件是否启用（设置页第 1 步的开关）；
- 端口是否和设置页一致（默认 6700）；
- Windows 防火墙是否拦了本机回环（一般不会）；
- NapCat 的 URL 末尾有没有 `/`（建议带上）。

---

## 3. 在 DSH 里配置

打开 **左侧栏「插件」→ QQ 机器人 → 设置**，按页面三步填：

1. **把 QQ 接过来**：确认「启用监听」打开，端口 6700，token 与 NapCat 一致。
2. **谁能指挥它**：填你自己的大号 QQ（每行一个）。只有这里列出的号私聊才有反应。
3. **它能干什么**：选权限档，填工作目录（bot 干活的地方），保存。

设置页顶部还有一张「周边程序」卡片：自动探测 NapCat（6099）和 AstrBot（6185）有没有在运行，
点「打开设置」就能跳到它们的 WebUI，不用记端口。

保存后插件会重启一次，NapCat 会自动重连——状态短暂变灰是正常的。

### 权限档怎么选

| 档位 | 能做什么 | 什么时候用 |
| --- | --- | --- |
| 只看不动（safe） | 读文件、查资料；写入和执行命令一律拒绝 | 只想让它看看、总结 |
| 正常工作（standard） | 在工作目录读写、执行命令；危险操作先发到 QQ 问你 | 日常推荐 |
| 完全放开（full） | 什么都能做，也不再问你 | 你完全信任、且只在自己机器上用 |

`standard` 下，遇到删文件、装软件这类操作，QQ 会收到一条「🔐 需要你批准一次危险操作 #编号」，回复 `/allow 编号` 批准，`/deny 编号` 拒绝；超时自动拒绝。

## 4. 试一下

在 QQ 里私聊小号，发：

- `/help` — 看支持的命令
- `/status` — 看连接状态、权限档、工作目录
- `帮我在工作目录里建一个 hello.txt，写一段自我介绍`
- `把 hello.txt 发给我` — 触发文件发送

## 5. 已经有 AstrBot 怎么办

分两种情况，选一种即可。

### 情况 A：只用本插件（推荐，最简单）

在 NapCat 里只保留指向 `ws://127.0.0.1:6700/` 的 WebSocket 客户端，AstrBot 不启动或不再管这个 QQ。

### 情况 B：保留 AstrBot，让 DSH 当它的「外挂」

适合你已经在 AstrBot 上养了机器人、不想推倒重来。原理：

```
QQ → NapCat → AstrBot（人设/记忆/聊天）
                    │
                    ├─ 模型判断「这句话要动手」→ POST → 本插件 → DSH 干活 → 回 QQ
                    └─ 其余消息 ── 照旧由 AstrBot 回复
```

**不用加任何指令**：AstrBot 的模型会先判断这条消息要不要动电脑（一次很小的 YES/NO 请求），
要动手才转给 DSH；不要动手就正常聊天，不会一问两答。

配置步骤：

1. 把 `astrbot_plugin_dsh_bridge` 整个文件夹复制到 AstrBot 的 `data/plugins/` 下
   （默认路径 `D:\AstrBot\data\plugins\`）。
2. 打开里面的 `main.py`，改顶部三行：
   - `DSH_BRIDGE_URL`：默认 `http://127.0.0.1:6700/bridge`
   - `DSH_TOKEN`：和 DSH 设置页的 Access Token 一致；都没填就留空
   - `OWNER_QQ`：你自己的 QQ 号
3. 在 AstrBot WebUI 的插件页重载这个插件（或重启 AstrBot）。
4. DSH 设置页把「接入方式」切到 **astrbot**。
5. QQ 里直接说话即可，例如「看看 D 盘还有多少空间」。

如果模型判断不准，可以改用显式指令：`!dsh 帮我看下工作区里有什么文件`，这条不经过判断直接执行。

本插件不需要连 NapCat，只要 DSH 设置页第 1 步的「启用监听」打开即可；桥接请求默认只接受本机。

## 6. 常见问题

**Q：为什么显示 NapCat 未连接？**
A：插件在等 NapCat 连过来。检查第 2 步的地址、端口、插件开关；连上后状态会自动变绿。

**Q：重启电脑 / 重启 DSH 后还要重新配吗？**
A：不用。配置保存在 profile 里，插件启动会自动监听；NapCat 启动后会自动重连（NapCat 自己也要设为开机启动）。

**Q：能让机器人在群里干活吗？**
A：目前只支持私聊。群聊需要额外的 @ 判断和多人权限模型，尚未实现。

**Q：能发语音、图片吗？**
A：目前只处理文本，图片/语音会被忽略。发文件通过 `qq_send_file` 工具或直接说「把 xx 发给我」。

**Q：回复太长被拆成好几条？**
A：设置页「单条回复最长字数」控制，默认 1800。

**Q：bot 说没有写文件的工具？**
A：它用的是 DSH 里的工具集；如果 DSH 里没装文件工具，让它改用 `craft` 的报告保存，或检查工作目录权限。

---

## 7. 安全建议

- 用小号，不要用主号。
- owner 只填自己；「额外放行」等同 owner 权限，慎加。
- 长期用请选 `standard` 或 `safe`，别默认 `full`。
- 工作目录尽量选一个专用目录，不要直接指向整个磁盘或系统目录。
- 本插件默认只监听 `127.0.0.1`，不要改成 `0.0.0.0`，除非你清楚后果。
